# Enroll in a shared domain

1. Select the domain from the actual role/task or the user's choice. Domain names are safe lowercase slugs. Inspect its agent index: reuse the matching responsibility node, otherwise choose a unique agent slug. Multiple agents share a domain; each keeps its own responsibility node and role-file binding.
2. Create a candidate in a separate Git worktree/checkout from the reviewed base. For a new domain, copy the layout and JSON definitions from `assets/graph/engineering/` relative to the init skill directory. Use the actual domain name. The two starter responsibility nodes illustrate multiple agents: instantiate only enrolled roles, rebuild their inverse relations, and retain shared starter guidance only where applicable. For an existing domain, preserve its schemas, nodes and other agents.
3. Read the actual role instructions. Distill that role's responsibilities with source pointers; connect applicable shared skills/flows and guardrails with their inverse edges. Keep domain facts in their outside source. Update `indexes/node-index.md` and `indexes/agent-index.md` from actual frontmatter. File placement and relation rules are in the domain's `indexes/schema-definition.md`.
4. Evaluate the candidate through `evolve-evaluate`, passing the exact domain, agent, base/candidate paths and retained diff. Before a workspace connection exists, pass the local evaluation directory explicitly. Validate all affected nodes, both indexes and incoming/outgoing relations, including existing agents.
5. Use [hosted review](../../evolve/references/hosted-review.md). Reuse an existing init review for the same enrollment. Completion: the review contains the exact assessed domain/agent changes and no unrelated agents' edits; shared activation awaits human merge.
