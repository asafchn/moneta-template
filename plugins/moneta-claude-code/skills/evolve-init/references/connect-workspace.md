# Connect the enrolled role

1. Use `assets/templates/workspace.md` relative to the init skill directory. Record repository URL, hosting, base branch, local checkout/graph root, separate evaluation root, and the actual agent/domain/role-file binding. Merge this binding into an existing connection; preserve other agents. Keep raw evidence and local checkouts under ignored `.moneta-local/`.
2. Follow `assets/templates/role-agent-addition.md` relative to init for the role file's format: Markdown gets a marked block; a Codex TOML role gets that guidance inside `developer_instructions`. Bind the active agent/domain explicitly and preserve responsibilities outside that block. Hosted role changes follow their owning repository's review flow.
3. Resolve installed skill names and supporting role files. Claude discovers the plugin's named agents. For Codex, install the bundled `agent-definitions/*.toml` relative to the installed Codex plugin root into the consuming project's `.codex/agents/`, preserving existing files and reporting a name conflict. Verify native discovery; until available, pass the bundled role Markdown to a native child explicitly. Host invocation names come from discovery, not a guessed namespace. See [distribution](distribution.md) when skills or roles are missing.
4. If enrollment is pending merge, report that state; ordinary retrieval stays on reviewed knowledge. After merge, refresh and invoke `knowledge-search` for the enrolled role, testing index/query, header discovery, direct walk and selected body reading. Completion: report the actual selected agent/domain and revision, or the specific pending integration step.
