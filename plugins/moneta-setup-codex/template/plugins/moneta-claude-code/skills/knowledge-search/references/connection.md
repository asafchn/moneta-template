# Resolve this runtime's connection

Use the originating generated plugin's moneta.json (the hook supplies its absolute path). An explicit skill invocation selects that skill's own plugin root. Resolve it with `node <runtime-root>/scripts/connection.cjs <absolute-cwd>`. Global availability works in any folder or chat and never inspects Git origin. The knowledge repository is storage, not a codebase binding. Restricted availability checks only local Git origin against explicit targets; profiles with nonempty legacy targets remain restricted until deliberately changed. The helper performs no network or organization discovery. If multiple runtimes are available, retain the user's explicit selection or ask which one before reading; never combine their graphs.

The profile supplies repository-url, hosting and base-branch. Resolve this plugin's manifest identity and use a private user directory `~/.moneta/<plugin-id>/`: repository/ for the reviewed local clone, candidates/ for proposals, evaluation/ for assessments, pending/ for saved source and config.json for machine-local checkout/graph-root paths, repository identity, revision and last-successful-pull-at. The local clone and config are required before any retrieval; never substitute hosted file reads. Use the actual user's home, not an isolated sandbox account's home. A child receives the explicit resolved connection; it never infers another runtime from its worker name. Agent-slug selection remains separate.

Reuse the connection only after verifying its repository identity. If absent, create its private directory and clone only the chosen knowledge repository with existing authenticated Git access. Initialize config.json using the runtime sync-state.schema.json with checkout, graph-root <checkout>/memory, repository identity, branch, and null revision/last-successful-pull-at until sync succeeds. Run the freshness procedure to establish a verified timestamp. Preserve legacy connection.md enrollment bindings; migrate its paths into config.json after identity checks without inventing a pull timestamp. A candidate graph or plugin installation cache is never the ordinary graph checkout. Do not recreate repositories for a missing local cache.

A legacy .moneta.md is an explicit local override. Preserve it; if it identifies a different knowledge repository, ask which connection to use rather than silently switching. Global availability needs no per-codebase file or repository setup. For an unmatched restricted profile, the user can ask init to remove that runtime's binding; preserve its destination/identity and memory areas while updating both native profiles and runtime versions. Invalid or unpersonalized profiles are unavailable, not a reason to create another repository automatically. Automatic feedback hooks cannot initialize repositories.

Evaluation and raw telemetry remain in the private user directory, outside the published graph. Global availability changes where the runtime can be used; it does not change agent-slug isolation, authorize reading another runtime, or grant provider permissions. Apply each retrieved node only within its stated task/domain scope.
