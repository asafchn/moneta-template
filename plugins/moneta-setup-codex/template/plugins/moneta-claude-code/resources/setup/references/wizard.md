# Setup wizard

Start with one sentence: "I'll create your memory repository and install its plugin." Ask only unanswered choices, one at a time. Reuse supplied context and answers; accept compact answers covering several fields. Keep successful checks in the review, with brief progress for authentication, preparation and installation. No organization enumeration, source-code scans or repository discovery.

1. **Provider and destination.** Ask GitHub/gh or GitLab/glab if not supplied by an explicit URL. Obtain the GitLab host when needed. Ask new or existing repository; existing needs its URL and keeps owner/visibility. New needs exact personal/organization namespace, repository name and explicit visibility (suggest private). An organization owner is not authorization to create a group or scan it.
2. **Authenticate once.** Use [verified access](authentication.md), preserving the approved execution context for subsequent operations. Account verification and the chosen knowledge repository are the only required remote lookups. Prepare independent local work while waiting for browser login if needed.
3. **Match codebases.** Ask which repository URL or organization/group URL should use this memory. Store the user-supplied rule, including subgroups for organization targets. Accept multiple explicitly named targets; do not fetch their contents or list their repositories. Explain once: matching reads only the open codebase's local Git origin. A group owning the knowledge repository does not automatically mean all its codebases are selected. A local repository remote may be offered as a suggestion; wait for selection when not explicit.
4. **Purpose (optional).** Follow [repository README](repository-readme.md). Ask once whether the user wants to describe the intended use; accept skip without more questions. Purpose changes README wording, never permissions or scope.
5. **Memory area.** Apply an explicit agent-slug; omission selects general. Ask about a role file only if the user requested enrollment and its path is missing. No additional scope question is needed for general.

When these answers are supplied, continue creating and installing without a redundant confirmation. Preserve the exact destination, matching rules, purpose and current stage on retries. Never replace an existing connection or plugin belonging to another destination; repeated init reuses the same instance and pending review. Material collisions, overlapping connections or requested changes to existing bindings go to the user.
