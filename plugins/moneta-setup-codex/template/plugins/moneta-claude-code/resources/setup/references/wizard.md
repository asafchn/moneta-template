# Setup wizard

First ask, unless already answered: "Start a new knowledge base, or connect to an existing one shared by your team?" Follow the selected path; do not presume repository creation. Ask only unanswered choices, one at a time. Reuse context and compact answers. Keep progress brief for authentication, local preparation and installation. No organization enumeration, source-code scans or repository discovery.

1. **Provider and destination.** Connect needs only the existing repository URL; infer hosting from it and retain the shared owner, visibility, purpose and plugin identity. New setup asks GitHub/gh or GitLab/glab if unknown, exact personal/organization namespace, repository name and visibility (suggest private). An organization owner is not authorization to create a group or scan it.
2. **Authenticate once.** Use [verified access](authentication.md), preserving the approved execution context for subsequent operations. Account verification and the chosen knowledge repository are the only required remote lookups. Prepare independent local work while waiting for browser login if needed.
3. **Availability.** Default a new runtime to global: it works in every project and ordinary chat, including outside Git. State this briefly and continue; no codebase-binding question is required. Only when the user requests restrictions, collect exact repository or organization/group URLs and set restricted availability. Matching then reads only local Git origin; never enumerate repositories. On repeat init preserve explicit existing restrictions unless the user asks to remove them. A request to make this runtime unbound authorizes global availability and removal of its targets; preserve its memory repository and agent areas.
4. **Purpose (optional, new setup).** Follow [repository README](repository-readme.md). Ask once and accept skip. Connecting a teammate reuses the existing purpose/README; do not ask them to redefine the team's knowledge base. Purpose changes README wording, never permissions or scope.
5. **Memory area.** Apply an explicit agent-slug; omission selects general. Ask about a role file only if the user requested enrollment and its path is missing. No additional scope question is needed for general.

When these answers are supplied, continue creating and installing without a redundant confirmation. Preserve the exact destination, availability, optional restrictions, purpose and current stage on retries. Never replace a plugin belonging to another destination; repeated init reuses the same instance and pending review. If multiple memory runtimes are available, use the explicit selection or ask which one; never merge their graphs or infer selection from the current codebase when global.
