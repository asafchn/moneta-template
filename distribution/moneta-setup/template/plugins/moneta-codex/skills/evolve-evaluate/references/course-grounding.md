## Admission and measurement

The lectures do not prescribe our node taxonomy, YAML fields, inverse edge names, Git review, a universal score threshold, or a fixed rule for what to add to a prompt/skill. Those are product choices. The agent should connect a proposed change to the original request, applicable responsibility, observed correction and its scope; check whether existing knowledge was missing, undiscovered or misapplied; and preserve a supported no-change option.

Existing deterministic tools establish the properties they actually check. A test pass does not establish full user satisfaction; retrieval precision needs relevance labels; an LLM judgment remains a judgment. Keep the criterion/version, source, command/output, task denominator, baseline/candidate condition and limitations. Compare future runs under matched conditions before claiming an improvement. These are evidence-minded adaptations of the course, not a claim that all nine lectures use one evaluation protocol.

No additional operational node type is required by the supplied passages. Task cases and feedback can support evaluation outside search; promoting them into searchable knowledge remains a user decision.
