# Select one memory area

Use this routing rule for init, retrieval, evolution, evaluation and every delegated step. The optional `agent-slug` argument follows the local `schemas/memory-request.schema.json` contract.

1. Read the invocation arguments. If `agent-slug` is absent, select `general`. If present, validate a lowercase hyphenated slug and select that exact value. Reject empty, null, path-like or malformed values; they do not mean general. A mentioned agent inside a transcript, the current role name, a stored binding and the delegated worker's name are not routing arguments.
2. Resolve the selected area as `<graph-root>/<selected-slug>/`. The personal repository uses `memory/` as graph-root, keeping independent agent areas within the knowledge repository. Retain this selection for the operation. Every nested skill call must pass `agent-slug: <selected-slug>` explicitly (including general when forwarding); the memory-scope record alone is not a routing argument. Pass the selection explicitly to children; never replace it with `evolve-agent` or `eval-agent`.
3. Read and write only this area's indexes, nodes, schemas and relations. An agent-specific read never also searches general or another agent. Missing knowledge or a missing area is reported, without fallback. Init may create the selected area through review. General is an explicit shared area only when selected, not a universal fallback.
4. Check resolved paths remain inside the selected area, including symlinks and relation targets. Slugs and inverse edges are area-local. A relation cannot cross into another area, even if its slug exists there. Validate only the selected area's graph; repository identity/status checks may inspect Git metadata without reading other areas' node contents.
5. Record the selected value as `memory-scope`. Separately record the actor/role when known, otherwise `agent: unassigned` for evaluation attribution. Role bindings locate applicable instructions inside the selected area; they never change selection. Evaluation access is confined to `evaluation-root/<memory-scope>/<agent>/` through evolve-evaluate.

An explicit user request to change scope starts a new operation. Moving old shared-domain nodes into agent areas requires an explicit ownership map and review; do not guess ownership or silently duplicate memories.
