# Existing personal repository

1. Resolve hosting from the supplied URL; ambiguous self-hosted domains need an explicit flag. Inspect checkout remote/state before reuse, otherwise clone with existing Git authentication. Verify this is the user's destination, not the bootstrap repository unless explicitly requested.
2. Discover and safely refresh the reviewed base branch. Preserve dirty/off-base work in a separate checkout. Ordinary retrieval follows [reviewed state](../../knowledge-search/references/reviewed-state.md).
3. An empty remote needs an empty base commit before an enrollment PR/MR. Publish only that base before the proposal. Retain the candidate locally if protected initialization is unavailable.
4. If the repository lacks the Moneta bootstrap, prepare missing bootstrap files in the review candidate from a verified `asafchn/Moneta` checkout (clone it into the ignored local area if needed). Preserve existing files, memories and repository identity; conflicting bootstrap paths need a reviewed merge decision rather than replacement. Copy versioned bootstrap sources/packages only, excluding Git metadata, local connections, telemetry and any live memory areas.
5. Use `<checkout>/memory/` for graph-root. Inspect only the selected area's schema/indexes. Preserve bootstrap files and other areas. A preexisting shared-domain or flat graph needs an explicit ownership/move map before migration: general or one specific agent per node. Raise ambiguous ownership or incompatible schemas for a user decision; preserve old data until reviewed migration completes.

Completion: personal URL, hosting, reviewed revision and selected area's state are known. Continue with enrollment. The review can add missing bootstrap files and the selected memory area together; unrelated files and existing personal customizations remain intact.
