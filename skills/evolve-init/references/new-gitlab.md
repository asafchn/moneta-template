# New personal or group GitLab repository

Reach this branch with the wizard's verified host/account, namespace, name and visibility. The destination can be a personal namespace or existing group/subgroup. Use glab for GitLab; Git access to the Moneta bootstrap does not require gh.

1. Inspect local `glab repo create --help` and verify the selected namespace is accessible. Resolve the exact destination URL, including the host. Prepare a clean bootstrap export from a verified Moneta checkout and record its revision. Include versioned plugin sources/packages and templates; exclude Git metadata, local connections, telemetry and live memory areas. Prepare enrollment separately from this initial bootstrap.
2. Query the exact project using the selected host's glab API/CLI. If it exists, verify destination and resume through [existing repository](existing-repository.md); never overwrite a collision. If the outcome of a previous creation is unknown, resolve it before retrying.
3. Create the project with explicit host/namespace, selected visibility and no local Git side effects. Private example: `glab repo create https://<host>/<namespace>/<name> --private --skipGitInit --defaultBranch main`. Replace visibility only with the wizard's actual choice. Main is the prepared bootstrap branch; honor an explicitly chosen permitted branch. Run in an isolated work directory. Verify installed flags before executing; do not rely on glab's default visibility or current remote/host.
4. Verify the returned project URL, namespace and visibility. In an isolated local repository, commit only the prepared bootstrap export, set origin to that verified personal/group project and push its initial branch without force. This is a bootstrap copy, not a cross-host GitHub fork. User-specific nodes and role changes stay in the separate enrollment MR. Preserve any existing remote commit and switch to the existing-repository flow if another writer initialized it.
5. Read the actual remote default/base branch and clone or safely reuse the new checkout. Completion: the user's project and bootstrap revision exist, and memory enrollment can open its MR. If creation succeeds but push or enrollment fails, return the created URL and precise pending action; do not recreate or delete the project.

Creation flags and host selection follow the [GitLab CLI create reference](https://docs.gitlab.com/cli/repo/create/). Project/group policies may restrict creation or visibility; report actual errors and retain prepared work locally.
