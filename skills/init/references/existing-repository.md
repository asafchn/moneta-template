# Connect to an existing knowledge repository

This is the teammate/onboarding path. Use [provider output handling](provider-output.md) and the exact URL the user supplied. Read access is enough to connect; proposing future improvements may need separate write access. No organization discovery.

1. Verify the supplied repository and its reviewed default branch. Reuse an identity-verified local checkout or clone that exact repository into the user's private Moneta directory. Preserve dirty/off-base work separately. Never copy the bootstrap over an existing repository.
2. Read its existing README, marketplace metadata and native manifests/profiles. Reuse its plugin identity, native runtime, schemas, indexes and graph. Do not ask for a new name, owner, visibility or replacement purpose, and do not generate/publish a fresh runtime merely to onboard a teammate.
3. Create this machine's config.json with the local checkout, graph-root and repository identity. Run the runtime's sync.cjs helper to verify the reviewed base and record the last successful pull before reading memory. An older runtime without the helper uses the documented [freshness procedure](../../knowledge-search/references/freshness.md) with existing Git tools until an explicit runtime upgrade is reviewed; do not silently rewrite the shared plugin.
4. Use an existing general area when no agent-slug was supplied; otherwise select only the explicitly named area. Existing usable memory requires no setup PR/MR. A missing requested area is a separate enrollment proposal, not permission to replace existing memory. An incompatible/non-Moneta repository needs one focused compatibility decision; an empty repository reaches the creation path only with the user's intent to initialize it.
5. [Install and enable](install-generated.md) the existing native plugin for this host. Preserve the team's profile and customizations. New global profiles work across projects; an existing explicit restriction remains until deliberately changed. Reuse local config/checkouts on repeated init.

Completion: this teammate has a verified local clone, machine-local config and the existing plugin installed/enabled. Return the shared repository URL and any host trust/reload step. A connect-only run creates no repository, commits, push or review request. If write access is unavailable, retrieval still works; future contribution steps explain the specific denied write and manual alternative.
