01 · Files

Three kinds of file.

The format, the catalog, the knowledge.

schema-definition.md
Explains fields, node types, edge schemas and both directions of each relationship.
node-index.md
Each searchable node’s slug beside its description.
One Markdown file per node
YAML frontmatter for discovery and links. Body for detail.

Local clone. JSON schemas define the format; native skills use existing file and Git tools.

02 · One node

Summary first. Detail later.

Common fields, shared by every type.

slug · node-type
Unique identity and the schema this node follows.
description · tags · scope
What it covers and when it matters. Used for discovery.
data
Fields specific to this node type.
relations
Named edges to other node slugs.
Body
Full guidance and examples. Loaded after selection.
See a Markdown node
---
slug: follow-pagination-tokens
node-type: coding-guidelines
description: Guidance for paginated API clients.
tags: [pagination, api, client]
scope: [coding]
data:
  rule: Follow returned continuation tokens.
  applies-when: Implementing a paginated client.
relations:
  - type: guides
    target: fetch-next-page
---
Check the external API documentation.
If tokens are opaque, pass them unchanged.

Illustration only. Actual guidance needs the API’s source, version and scope.

04 · Relationships

Meaning in both directions.

Each edge schema defines names, meanings and allowed source/target types.

follow-pagination-tokensguides ↓fetch-next-page
fetch-next-pageguided-by ↓follow-pagination-tokens

The edge name explains how each endpoint relates to the other.

Storage choice

Store each direction in its node’s frontmatter. Validate that both match; update both files together.

This implementation stores mirrored entries. JSON Schema checks shape; the agent checks cross-file consistency.

05 · Discovery

Index → query → knowledge.

The agent predicts what it needs from the catalog.

Read the index
Slug + description. Generate a query for the intended work.
find
Tokenize the query. Search frontmatter metadata and descriptions.
walk
Inspect direct relationships. Select relevant connected nodes.
read
Load full bodies of selected nodes.
See an index entry
follow-pagination-tokens
  Guidance for paginated API clients.

The agent updates the index alongside node changes, keeping descriptions aligned.

Role instructions invoke this workflow. An enforced pre-action hook is not included in the declarative package.

06 · Access boundaries

Three ways to reach information.

Agreed separation.

Operational knowledge
The typed Markdown graph. Access through index, find, walk and read.
Domain knowledge
Outside source. Use that source’s access method; keep facts there.
Evaluation criteria + results
Access through a different skill. Excluded from ordinary graph search.

node-index covers ordinary searchable knowledge only.

Connection file names the external source and separate evaluation directory. Evaluation uses evolve-evaluate.

07 · Review

Review before shared learning.

A session yields a supported proposal, not an automatic permanent rule.

Analyze
Compare the request, role intent, delivered work and human corrections.
Evaluate
Separate agent review from executed checks. Record tools, outputs and defined metrics.
Propose
Update applicable knowledge, both edge directions and the index. Open an MR/PR.
Activate
Human merge. Later agents refresh their local clone and retrieve reviewed guidance.

Graph choices are our implementation. Stanford does not prescribe this schema or a universal admission score.
